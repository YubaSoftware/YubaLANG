# Migrating from YubaLANG 1.3 to 1.4

YubaLANG 1.4 is an additive minor release. Documented 1.3 programs continue to
run without changes. The complete syntax and behavior are in the
[1.4 language reference](../1.4-docs.md).

## New syntax

Expressions may now call functions. Use a name or imported namespace, and pass
positional or named arguments:

```hl
func define double value:int -> int
    return value * 2
endfunc

define var total: int = double(3) + double(value=4)
text output total
```

`func call` remains the command form and is still the clearest choice when a
call's result is discarded. `range(...)` and `set()` keep their existing
expression behavior. Attribute/index expressions, method receivers, argument
unpacking, and calls on call results are not supported.

Record fields may have defaults, and construction accepts named values after
positional values:

```hl
record define Settings retries:int=3 label:string="default"
record create Settings first
record create Settings second label="strict"
record create Settings third 5 label="named"
```

Defaults are evaluated for each construction. Mutable defaults are not shared
between records. A default may read a variable that exists when the record is
constructed. A record field type may refer to a record defined later in the
same file; the referenced record must be defined before a value containing it
is constructed.

## New tools

Debug a program interactively:

```text
YubaLANG debug --break 2 --break helper.yl:10 main.yl
```

The debugger supports `continue`, `step`, `next`, `finish`, `stack`, `vars`,
`list`, breakpoint management, and `quit`. Prompts and diagnostics are written
to standard error.

Collect opt-in test coverage:

```text
YubaLANG test --coverage tests/cases
```

Coverage adds a percentage summary and uncovered executable lines. Without the
flag, test output and JSON reports are unchanged.

## Resource cleanup

Files opened with `open` still close automatically when execution ends, now
through the general resource protocol. Hosts that provide resources can
register them with `Runtime.register_resource`; cleanup runs in reverse
registration order, attempts every resource, and raises the first close error
after all cleanup has been attempted. `close` remains the early-closure command
for files.

## Compatibility notes

- Existing command forms, positional record construction, and `func call`
  statements remain valid.
- Manifests targeting `1.2` and `1.3` remain accepted. New projects target
  `1.4`.
- The test runner and LSP default behavior are unchanged for existing tools;
  coverage is opt-in, and workspace-wide rename skips ambiguous or local-only
  matches.
- Record methods, inheritance, code-running constructors, concurrency, async
  I/O, build/bundle commands, and registry resolution in the runtime remain
  deferred. Registry resolution stays in YubaPKG.

See the [1.4.0 release notes](1.4-release-notes.md) for the full feature list.
