# Migrating from YubaLANG 1.3 to 1.4

YubaLANG 1.4 is an additive minor release. Documented 1.3 programs continue to
run without changes. The complete syntax and behavior are in the
[1.4 language reference](../1.4-docs.md).

## New syntax

Expressions may now call functions. Use a name or imported namespace, and pass
positional or named arguments:

```hl
func define double value:int -> int
    return value * 2
endfunc

define var total: int = double(3) + double(value=4)
text output total
```

`func call` remains the command form and is still the clearest choice when a
call's result is discarded. `range(...)` and `set()` keep their existing
expression behavior. Expressions also support attribute, index, slice, and
method access with chained receivers, lambdas, optional chaining, and argument
and literal unpacking:

```hl
define var names: list[string] = ["Ada", "Grace"]
define var double: (int) -> int = lambda value: value * 2
define var maybe: string | none = none
text output names[0].upper()
text output map(double, [1, 2, 3])
text output names ?: []
```

`loop for <target> in <iterable>` iterates collections and other iterables;
targets may destructure tuples and lists. Declarations and `set` also accept
tuple/list destructuring.

Enums and `match`/`case` add sum types and pattern dispatch:

```hl
enum define Result ok(value: int) error(message: string)
enum create Result.ok success 42
match success
    case Result.ok(value)
        text output value
    case Result.error(message)
        text output message
endmatch
```

`type define <name> = <type>` declares a type alias. `define const` declares an
immutable variable, and a `const` marker makes a record field immutable.
Compound assignments (`+=`, `-=`, `*=`, `/=`, `//=`, `%=`, `**=`, `&=`, `|=`,
`^=`, `<<=`, `>>=`) apply the same declared-type rules as `set`.

Record fields may have defaults, and construction accepts named values after
positional values:

```hl
record define Settings retries:int=3 label:string="default"
record create Settings first
record create Settings second label="strict"
record create Settings third 5 label="named"
```

Defaults are evaluated for each construction. Mutable defaults are not shared
between records. A default may read a variable that exists when the record is
constructed. A record field type may refer to a record defined later in the
same file; the referenced record must be defined before a value containing it
is constructed.

## Runtime and standard-library additions

The standard library adds `std.regex`, `std.glob`, `std.tempfile`,
`std.archive`, `std.sqlite`, `std.uuid`, `std.decimal`, `std.statistics`,
`std.logging`, `std.terminal`, `std.env`, `std.io`, and `std.sys`. Existing
`std.re`, `std.statistics`, and `std.sqlite` imports keep resolving, but their
function sets have expanded and their handles now use the resource protocol.
`std.sqlite.connect` is replaced by `std.sqlite.open`, which returns a handle
dictionary accepted by the other SQLite functions.

File I/O adds sized reads, `readline`/`readlines`, `writelines`, `seek`,
`tell`, `flush`, `truncate`, and line iteration through `iter`. Existing
`file read <file> <destination>` and `file write <file> <value>` forms are
unchanged. `std.fs` adds atomic replacement and sorted listing helpers, and
`std.io` exposes binary standard streams.

A named catch variable now receives a dictionary with `kind`, `message`,
`code`, `cause`, `stack`, and `value` instead of a raw thrown value or message
string. Its string form is still the message, so `text output problem` produces
the same output. Code that compared the catch variable to a string or inspected
its type should use the dictionary fields. Use `catch <kind> as <variable>` for
filtered handling and `error <kind> <message> <destination> [cause]` to create
an error value explicitly.

Recursion depth, collection size, HTTP bounds, and subprocess bounds are now
configurable and default to the values documented in the
[standard-library reference](../features/standard-library.md#runtime-limits).
Existing programs that stayed within the previous 128-call and 1 MiB defaults
continue to run. A collection larger than 1,000,000 top-level entries now raises
`limit-error` unless the host or program raises `max_collection_size`.

## New tools

Debug a program interactively:

```text
YubaLANG debug --break 2 --break helper.yl:10 main.yl
```

The debugger supports `continue`, `step`, `next`, `finish`, `stack`, `vars`,
`list`, breakpoint management, and `quit`. Prompts and diagnostics are written
to standard error.

Collect opt-in test coverage:

```text
YubaLANG test --coverage tests/cases
```

Coverage adds a percentage summary and uncovered executable lines. Without the
flag, test output and JSON reports are unchanged.

Check source with stable diagnostic codes and CI-friendly modes:

```text
YubaLANG check --strict --json main.yl
YubaLANG explain type-mismatch
```

`check` still fails only on errors by default. `--deny-warnings` fails when a
warning is reported, and `--strict` enables strict-only annotation checks and
also fails on warnings. Existing `check` output remains valid; the code is
appended in brackets and the JSON schema is opt-in. See the
[diagnostic reference](../features/diagnostics.md).

## Resource cleanup

Files opened with `open` still close automatically when execution ends, now
through the general resource protocol. Hosts that provide resources can
register them with `Runtime.register_resource`; cleanup runs in reverse
registration order, attempts every resource, and raises the first close error
after all cleanup has been attempted. `close` remains the early-closure command
for files.

## Compatibility notes

- Existing command forms, positional record construction, and `func call`
  statements remain valid.
- Manifests targeting `1.2` and `1.3` remain accepted. New projects target
  `1.4`.
- The test runner and LSP default behavior are unchanged for existing tools;
  coverage is opt-in, and workspace-wide rename skips ambiguous or local-only
  matches.
- New expression, loop, destructuring, enum, match, alias, lambda, constant,
  compound-assignment, optional-chaining, and unpacking forms are additive; no
  documented 1.3 program changes meaning.
- `check` reports the same diagnostics as before plus new warnings. Runtime
  output keeps its wording and gains a bracketed code; runtime checks still
  decide what a program accepts.
- `non-exhaustive-match`, `invalid-pattern`, and `constant-reassignment` are
  active codes for the implemented match, pattern, and constant rules. They are
  listed in the [diagnostic reference](../features/diagnostics.md).
- User-defined generics, record methods, inheritance, code-running
  constructors, generators/`yield`, cleanup/defer forms, concurrency, async I/O,
  build/bundle commands, and registry resolution in the runtime remain
  deferred. Registry resolution stays in YubaPKG.

See the [1.4.0 release notes](1.4-release-notes.md) for the full feature list.
